# Decisions
- Docker Desktop was stopped at start; launched it programmatically (Windows). Baseline server+web tests green on v1.
- FEATURE_FREEZE 04:30 IST, HARD_STOP 07:00 IST (brief gave no times).
- Reference screenshot lives at docs/desgin/image.png (typo'd dir); used as design reference, not renamed.
- Existing migrations 001-004 (scenario_*) stay as files (001 untouched; 002-004 alter scenario tables so fresh DBs still migrate); v2 meta schema is migration 005. Same version table `scenario_schema_migration` is reused (renamed in meaning only).
- Retired server routes: accounts, playback, sim, scenarios, info(+checks). Kept services/playback+accountState (lab/stepper/strategies depend on them) but no UI route; leaseReaper removed.
- shared package consumed as TS source (main -> src/index.ts); no build step.
- [D] pinCurrent reuses ANY existing revision with the same content hash (meta table has UNIQUE(project_id, content_hash)), so A->B->A edits return the older revision with created=false.
- [D] Template master projects are seeded archived with a deterministic UUID (sha1 of key) so seeding is create-if-missing without races and they stay out of the Projects list; instantiate copies from code.
- [D] POST /validate = shared validateDesign + scratch-schema DDL apply (errors mapped to tables) + PREPARE of every workload step/invariant (errors mapped to txn/variant/step); scratch DBs are dsim_scratch_<id>_<rand>, always dropped, stale ones dropped at startup.
- [D] POST /schema/import runs pasted DDL as admin, so only CREATE TABLE / ALTER TABLE / CREATE INDEX with unqualified names are accepted; identifiers are lowercased with a warning; imported tables get seedRows 100.
- [D] Normalization is pure TS in shared/src/normalize.ts (max 16 attributes, bitmask closure); route imports it relatively until the lead exports it from shared/src/index.ts.
- [D] T1 search_sections has a third param min_seats (0..9) so the cache key space is ~1,440 and cache misses actually reach MySQL (144 keys would make every read a hit and hide the missing slot index).
- [D] T2 claim derives the account from the client row (client zipf param) because the composite FK needs a consistent (client_id, account_id) pair; hot clients make hot accounts. Quota-1 "hot lab" subset is approximated by quota weights 50/30/20 (seed generators cannot see the row index).
- [D] T1 section seed raised 1,200 -> 12,000 and search_sections uses STRAIGHT_JOIN (sections first): with 1,200 rows and the FK index on course.dept_id MySQL drives from course and never scans section (no FULL_SCAN finding); at 1,200 rows the index also changes db time by <0.2 ms (noise). At 12,000: search db_ms 4.4 -> 3.1 ms after ix_section_slot, p95 227 -> 198 ms (still queue-dominated at 200 VUs). Revert by changing one number in templates/t1CourseRegistration.ts.
- [D] T3/T4 map unordered/ordered locking and naive/atomic onto the shared strategy enum: T4 unordered = `naive` (and default), ordered = `pessimistic`. T4 bank_meta holds opening_balance per account (invariant = SUM(balance) = COUNT(*) * opening) so it stays correct under rowScale.
- [D] Outcome tests wait up to 2 min for the global run lock (RUN_ACTIVE) so concurrent builders' runs do not fail them.
- [A] Latency model: edge latency is one-way; each app->DB statement and the COMMIT pay one link round trip (2x latency, real await, holds locks), users->[lb]->app hops are paid again on the way back. Redis lookup pays 2x the app->redis latency plus the real GET.
- [A] TPS = committed + rejected responses per second (errors excluded); latency percentiles include all outcomes. Percentiles come from a 1%-resolution log-bucket histogram (no per-request arrays).
- [A] Live samples emitted during warm-up carry tS <= 0 (tS = elapsed - warmupS); only samples with tS >= 1 are persisted, so live tS == persisted t_s. Capacity steps are laid end to end (tS offset by the previous steps' measured seconds).
- [A] Digest stats: events_statements_summary_by_digest is TRUNCATEd when the measured window starts (falls back to a before-snapshot delta if TRUNCATE is refused), so rows are measured-window only; statements are mapped to transactions through STATEMENT_DIGEST() of the template with sample literals. Com_* deltas come from events_statements_summary_global_by_event_name because global Com_* status only merges at session close.
- [A] Lock-wait attribution: each pooled connection's threadId is mapped to the transaction it currently runs; data_lock_waits is joined to performance_schema.threads (PROCESSLIST_ID) at <= 2 Hz; persisted rows are de-duplicated against the previous snapshot (max 500 rows).
- [A] Capacity runs re-provision before every step when the workload has writes and seeding is <= 30,000 rows (else provision once): otherwise later steps would run on state mutated by earlier ones (full sections, grown tables). Run-level metrics, txn stats, statements, invariants and findings come from the largest step that still meets the SLO (else the first step); counts are summed over all steps; every step is analysed while its own DB state exists. Verdict PASS only if no step breaks the SLO or hits the knee.
- [A] Knee = first step with TPS gain < 10% and p95 > 1.5x the previous step, or SLO break; sustained = largest step with every step so far inside the SLO. The report sentence interpolates the p95/SLO crossing between the last passing and first failing step.
- [A] USL fit: grid over (sigma, kappa) + Nelder-Mead on sigma=a^2, kappa=b^2 (so both stay >= 0), lambda closed-form per candidate; nPeak is capped at 1e6 (kappa ~ 0 means no retrograde region, xMax = lambda/sigma).
- [A] Global run exclusion: in-process flag (engine/active.ts) reserved synchronously + MySQL GET_LOCK('datasim_run') on a held appPool connection; design/Redis validation runs BEFORE the lock so a broken design answers 400 even while another run is active. Stale non-terminal runs are failed at startup (routes/runs.ts import) only when the lock is free.
- [A] `serializable` strategy only changes transactions that define a `serializable` variant (forces SERIALIZABLE for that txn); use the isolation selector for a global level. `definedVariants` for compare-strategies drops `default` when an explicit `naive` variant exists.
- [A] Retry policy covers deadlock 1213, lock wait timeout 1205 and expectAffected{onFail:'retry'} (CAS); backoff = backoffMs * 2^attempt * U(0.5,1.5), counted in the app phase. 1062 and 3819 become REJECTED; 1452, 3024 and everything else ERROR. max_execution_time only affects SELECT (MySQL limitation).
- [A] Test-once and the SQL console run as dsim_runner; the console wraps queries in START TRANSACTION READ ONLY with sql_select_limit 201 and max_execution_time 5 s.
- [A] Phase accounting: net = link sleeps + Redis GET; app = emulated processing + retry backoff; pool = getConnection wait; db = SET/START/statements/COMMIT/ROLLBACK round trips measured with hrtime. Under a saturated event loop timers overshoot and the overshoot lands in net/app (wall clock is honest, phase split is approximate).
